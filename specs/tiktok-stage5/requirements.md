# 阶段 5：TikTok 商品视频

用户已登录国际版 TikTok 并要求开始开发。沿用浏览器发布插件；不接入未配置的 Direct Post API。开发上传测试片段已获单独授权，真实作品发布必须在成片与文案确认之后。

1. 从当前空间的商品视频创建独立 TikTok 工程，复制素材、镜头与音轨，清空旧导出和旧确认；修改、重开不改变小红书或抖音工程。
2. 目标语言与市场可编辑，默认英语／国际受众。配置文本模型可提出发布文案、逐镜头字幕与旁白建议；确认前不改工程，不生成视频或语音。不能编造商品规格、价格、功效、海外销售或认证。
3. 建议的商品、版本与工程状态须在主进程复核；无效镜头、过期建议、空间变化拒绝应用。应用语言修改后旧音轨标为待处理，不自动付费生成，旧导出须重新核验。
4. 发布只使用当前 TikTok 工程的最新导出 MP4；绑定浏览器实例、实际账号、版本与内容摘要。明确选择可见范围、评论与内容标记后生成确认；上传供核对与点击 Post 分开。
5. 插件在 TikTok Studio 的实际 DOM 上识别空白上传页、原任务草稿与媒体，回读文案及设置；用户已有草稿、错账号、错媒体、验证码及无法核对的控件不得覆盖或提交。
6. 重复确认幂等；上传／提交期间中断保留记录。未知回执不自动重投，已发布不再次提交。需要人工核实的结果在界面明确展示。
7. 自动测试覆盖独立版本、空间／版本隔离、模型建议校验、媒体与账号归属、发布设置回读、提交幂等、未知结果和恢复。真实账号实际发帖只在用户明确确认后验收；未验项目留档。

参考：[TikTok Studio](https://support.tiktok.com/en/using-tiktok/creating-videos/creator-tools-on-tiktok)、[API 分享要求](https://developers.tiktok.com/docs/en/content-sharing-guidelines)。API 的审核流程不作为浏览器上传的已通过证明。
