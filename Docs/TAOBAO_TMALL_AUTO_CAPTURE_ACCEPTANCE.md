## 实现范围

- 「计划 → 自动化」新增「淘宝商品自动采集」「天猫商品自动采集」，分别默认关闭，默认时间 11:00／11:30。配置沿用京东任务：关键词、目标新增商品数、评论标签、每标签条数、节奏和执行时间；就绪检查要求关键词及已连接采集插件。
- “立即运行”在定时开关关闭时也执行一轮，执行前仍检查就绪状态与串行占用；不开启定时任务，也不安排下次执行。修复了手动运行被关闭开关静默跳过、没有运行记录的问题。
- 按天轮换关键词，插件从平台首页实际搜索框提交，等待与滚动读取可见商品链接。首页推荐和另一关键词的旧搜索不能作为结果；普通搜索表单在任务自己的标签内提交，平台新开搜索页只接管任务搜索页产生的子标签。
- 详情页通过 `expectedProduct` 验证搜索卡片商品编号，复用侧栏的 `capture.save`、商品适配器、媒体安全下载和 `assets.ingestProduct`。来源按实际详情页识别，支持淘宝／天猫同编号跳转，不强行按搜索入口归类。保存前对未读到的价格、参数和详情增加最多 6 秒的等待与内部容器滚动，评价区域或完整列表入口未出现时再用独立最多 6 秒预算查找；缺失字段不会由标题或结构化 offers 推测补齐。
- 天猫详情域名支持 `detail.tmall.com` 和天猫超市 `chaoshi.detail.tmall.com`，两者均归为 `tmall`。同平台同编号只追加快照，淘宝来源保持独立；搜索卡片、注入提取、页面识别、侧栏、自动保存及主进程入库使用精确域名校验。图片服务域名和下载校验沿用原规则。
- 详情打开使用卡片原始 `navigationUrl`，保留页面提供的全部查询参数和片段；规范化 `sourceUrl` 单独用于身份和来源。插件及桌面端不再把原始导航地址清成 `id + skuId`。多个同商品链接优先保留参数更完整的原始地址，导航域名、编号及已声明 SKU 不一致时拒绝打开；不强制把天猫地址改成淘宝，也不复制另一个商品的示例参数。
- 默认采当前评价列表 5 条，可指定真实标签、每标签 1–50 条，不推断好中差。有限等待、滚动和下载沿用已验证的详情采集机制。
- 复采追加快照、不占新增配额；跨平台商品保持独立。新增不足目标时报告实际数量。搜索补读最多 2 次，尝试上限为 max(12, 目标数 × 4)，目标数上限 20。
- 登录、验证、限流立即停止；评论受限时已读商品保存为部分评论快照，整轮标记停止，成功商品 ID 与统计保留。淘宝／天猫编号不一致候选跳过，在原尝试预算内继续补足目标；连续两个其他采集错误停轮，显示具体原因。新增目标未满但已保存或复采时显示“部分完成”，不显示整轮跳过或成功。
- 所有采集任务共用已有串行调度锁、配置持久化和定时机制。任务结束关闭自己创建的详情页、搜索页及搜索子标签，不关闭用户原有页面；错误返回携带任务标签清理信息。
- 桥接按请求类型选择采集／发布插件，不按所有插件的最近活跃顺序混选。每轮商品与小红书采集在开始时固定采集实例；搜索、保存、清理都使用同一实例，断开后明确失败，不切换到另一个浏览器或发布插件。
- 报告按任务 ID 与空间隔离，整轮商品保存固定到任务启动空间；执行中切换界面空间不把商品、图片或来源快照写入另一空间。不修改当前创作会话或确认卡。采集不调用生成模型，不产生新视频生成费用。

## 真实任务验收步骤

1. 使用本轮最新桌面端及配套采集插件，保持已登录浏览器和桌面端运行。在「计划 → 自动化」配置淘宝任务：关键词“伟嘉成猫猫粮”，目标新增数 1，评论标签留空、采样 5，保守节奏，保持定时开关关闭，点击“立即运行”。结束后应保留运行记录与采集报告，定时开关仍关闭且下次运行未安排。
2. 核对实际页内搜索、搜索结果详情编号、资产库资料／评论／图片、报告统计与来源；若已有同来源商品，只追加快照，报告应说明复采。复采不计为新增，整轮仍有尝试上限。
3. 同样运行天猫任务，确认来源按实际详情页保存；不同来源商品独立，既有工程和创作确认卡不改变。
4. 将一个任务的时间设置为稍后的本地时间，等待定时触发，核对独立报告、任务自有标签清理和用户原标签保留。出现登录、验证或限流时停止，不继续重试。

本轮没有通过 Codex 工具执行受限制站点的真实搜索或采集，也没有把离线通过记为真实任务通过。后续以 GardenFlow 实际运行结果补充验收记录；用户无需重复保存此前已经人工确认通过的六件商品网页。
