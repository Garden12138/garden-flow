# 阶段 4：淘宝／天猫商品与评论采集验收

记录日期：2026-10-09（含此前安装包验收、用户保存页回放及真实采集后的本地资产核对）。范围为手动采集、来源回看、现有商品创作兼容和同款关系。工程实现、保存页面离线回放、已入库数据核对与原页比对分别记录；本阶段尚未完成全部真实页面验收。

## 已实现

- 商品适配器统一识别、商品提取、评论预览和采样，保留京东原入口及自动任务。淘宝和天猫分别保存为 `taobao`、`tmall`；Chrome MAIN 注入函数不依赖模块闭包。
- 读取名称、品牌、店铺、当前选中规格、可见价格、参数、描述、商品图和详情图。缺失字段明确标记，结构化 offers 不替代缺失的当前价格。
- 评论默认采当前列表 5 条，支持页面标签及每标签独立 1–50 条；完整保存读取到的买家正文、商家回复，评论图片独立下载。采用最多 6 次滚动、连续无新增停止、标签切换等待；验证、登录或限流出现后停止，保留已读取资料并提示未完成。下载图片按既有安全总量上限处理，未下载项保留来源及失败／跳过状态。
- 插件显示实际平台、时间、规格、价格和评论提示；资产库可切换同一平台的历史快照，查看评论采样统计及来源链接。
- 沿用平台与商品标识去重，同平台重采追加快照，保留用户修改和本地素材；跨平台商品始终独立保存。
- 独立同款关系只含关系 ID、两端商品 ID、确认时间和依据。主进程验证两端版本，拒绝过期推荐，重复确认幂等；解除和删除清理关系时保留另一商品。关系变化不改变商品事实、版本或创作确认状态。
- 配置的文本模型按品牌、型号及规格等资料语义推荐，最多 3 个候选；每批最多 40 个候选，较大目录逐批筛选。验证模型返回 ID，按当前目录绑定版本；失败显示原因并可手动选择。支持现有 OpenAI、Anthropic、Gemini 文本连接协议。
- `assets.ingestProduct` 使用平台身份与图片域名校验；每跳重定向先验证，检查 MIME 与文件签名，按流限制每图片 12MB。
- 桌面 bridge／IPC 增加 `suggestProductLinks`、`linkProducts`、`unlinkProducts`。旧目录缺少关系字段仍可读取，原商品 ID、素材路径和工程引用有效。
- `@商品` 保持读取被选商品自身的事实、快照和素材，同款关系不扩展创作输入。
- 自动调用 `capture.save` 复用淘宝／天猫详情页的商品与评论采集链路。接口声明支持三个商品平台、每标签独立数量，未传评论配置时仍默认 5 条；任务反馈按实际商品类型显示数量，保存结果返回评论状态和访问限制代码，供后续调度停止及报告使用。淘宝／天猫关键词、批量和定时内置任务仍未实现。
