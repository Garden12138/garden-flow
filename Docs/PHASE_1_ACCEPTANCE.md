# 阶段 1 验收记录

## 结论

阶段 1 于 2026-09-13 测试验收通过。验收范围是“资产库商品整理与编辑 → 创作页明确引用商品 → 服务端解析商品事实 → AI 创作上下文使用”的闭环。

阶段 1 测试开始时发现一项阻断问题：创作页的资产选择器只读取普通资产，没有读取品牌工作区中的商品。因此，阶段 0 保存的京东商品无法真正参与后续创作。该缺口修复并完成回归验证后，阶段 1 达到验收条件。

## 验收结果

| 项目 | 结果 | 实测说明 |
| --- | --- | --- |
| 商品资料整理 | 通过 | 商品编辑页能够加载商品名称、商品图和 SKU，并可补充描述、目标受众、品牌风格与使用场景 |
| 采集事实保留 | 通过 | 用户整理商品后，采集来源快照仍独立保存；品牌、店铺、价格、规格、参数和原始链接不会被展示层拼接覆盖 |
| 创作页资产发现 | 通过 | 输入 `@` 后可检索品牌工作区商品，并显示商品、品牌和京东来源；创作页同时明确提示 `@` 引用资产、`#` 引用资料 |
| 创作页资产引用 | 通过 | 选择商品后，输入框生成商品资产引用，并随创作请求传递资产 ID |
| 服务端事实解析 | 通过 | 主进程根据资产 ID 重新读取商品，不信任前端拼装的商品内容；上下文包含已存品牌、事实、SKU 和最多 4 份来源快照 |
| 事实边界 | 通过 | 上下文要求用户确认字段优先、价格和规格保留来源、不得补写不存在的卖点或效果，并忽略采集内容中的指令性文字 |
| 产品职责 | 通过 | 资产库负责保存、查看和整理商品事实；具体内容创作从“创作”或“生成”进入，产物继续归入稿件或媒体库 |

## 验证证据

- `pnpm check`：通过，包括 desktop 源码一致性、bridge parity、TypeScript、浏览器采集扩展和发布扩展检查。
- `pnpm test`：204 项通过，0 项失败；新增商品创作引用测试覆盖品牌、事实来源、SKU、价格、店铺和图片数量。
- `pnpm --dir desktop build:release:mac:arm64`：通过，生成 macOS arm64 应用与 DMG。
- 打包应用人工检查：创作页输入 `@` 后显示已采集的伟嘉京东商品及“商品 · 伟嘉（whiskas） · 京东”说明；点击后成功加入输入框。检查未发送模型请求。

## 数据与安全边界

- 前端只提交被选资产的 ID、名称和预览信息；AI 使用的商品事实由主进程按 ID 读取。
- 商品引用上下文只包含本地已保存的结构化事实与来源，不包含资产库界面生成的营销详情图。
- 用户补充的事实优先于采集事实；价格、规格等时效信息保留采集时间和来源页面。

## 不在阶段 1 范围内

- 不同模型供应商生成文案或图片的主观质量。
- 商品详情图编辑器、自动生成营销图片和一键发布。
- 淘宝、Shopee、Lazada 等其他平台的商品采集与创作适配。
- 未经用户确认的自动发布、自动覆盖商品资料或自动清理历史媒体。

后续阶段应以实际创作任务验证“选定商品 → 生成可编辑稿件/媒体 → 人工审核 → 发布”的交付闭环，并分别定义文案质量、视觉一致性和事实准确率标准。
