# 两周执行与复盘

目标：10 人实际试用、5 人完成首次创作、3 条可行动反馈。时间表从材料验收后开始，不是自动发布或定时任务。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 第 1–3 天 | README、下载说明、教程、公开样例与 GitHub 设置 | 链接和安装说明可用 |
| 第 4–5 天 | 跑通真实流程，制作录像和预览 | 有可回看的稿件、来源和实际媒体结果 |
| 第 6–7 天 | 维护者邀请少量试用者，完成首屏理解测试 | 有真实回复；不以邀请人数充当试用人数 |
| 第 8–10 天 | 根据失败步骤修正文档，审核小红书和掘金草稿 | 文案与演示一致，所有待核对段落清除 |
| 第 11–14 天 | 维护者发布、回复反馈并复盘 | 记录实际渠道、时间、结果和下一步 |

## 指标口径

- 试用人数：自愿确认已安装并开始教程的独立参与者，以匿名编号去重。
- 完成人数：确认有保存后可重新打开、带来源的稿件；图片为可选项。
- 可行动反馈：包含明确步骤、期望与实际结果，或明确的使用障碍；重复问题合并。
- 下载次数：GitHub Release 各安装包的累计下载增量，不计校验文件；重复下载和维护者验收都可能增加计数，不等于人数。
- 仓库访问：GitHub Traffic 在可用权限和保留窗口内提供的 views / uniques；发布前、发布后及时记录。
- Star：记录起止值和净变化，不将同时间发生的变化直接归因给某个渠道。
