# 成组内容（开发版）

在「计划 → 成组内容」中，围绕一个目标组织不同职责的内容。它复用已有机会、证据、创作工程和发布服务；归档内容组会保留工程与历史关联。

## 建立与规划

1. 在灵感页核对证据并采纳机会。
2. 建立内容组，选择目标、读者、商品、平台、已采纳机会及限制。
3. 点击「核对规划依据」，查看原文可定位状态、来源版本和商品目录资源。目录中登记的素材未逐一核对文件可用性，不能据此声称已有成片。
4. 手工添加内容项，或点击「去对话规划（先填草稿）」。后者只向现有对话填入草稿，由你决定是否发送；模型调用和工具确认沿用普通对话流程，可能产生文本费用。

现有 Agent 可通过 `campaign_read` 读取本组真实范围，再用 `campaign_propose` 保存3–8条、至少三种角色的候选。角色包括认知、教育、顾虑解答、演示和购买前支持。候选必须引用本组机会的真实证据 ID，并使用当前支持的平台与内容形式。虚构引用、过期机会版本、不支持目标和重复候选会被拒绝。

模型只保存待复核候选，不确认列表、不创建工程、不生成媒体、不上传或发布。角色分工、创意理由和素材需求估计仍需人工核实；原文可定位不代表商品主张可信，其他规格评价不能证明当前规格的体验。没有可用模型时可完成手工规划。

## 逐项进入创作

每组最多8条。尚未尝试创建的条目可修改，条目可排序；依赖只能指向前面的条目，用于策划顺序。修改列表后需要重新确认。

先核对至少三条不同角色并确认当前列表，再勾选、确认创建其中一条。每条都有独立工程与任务要求，复用原机会的来源验证和版本保护。进入编辑器可展开「成组内容任务」和「创作依据」，回看职责、限制与原始证据，然后手工编辑或通过现有创作对话继续工作。

创建工程不表示内容已完成，也不生成付费媒体。生成、上传供核对和最终发布继续逐项使用现有确认，不提供批量最终提交。

## 状态与恢复

- 工程可读时提供编辑入口；文件缺失时保留关联并显示缺失，不自动重建。
- 历史导出与发布分开显示；人工声明、已提交和可信回执保留各自来源。状态记录较多时提示部分加载；观测数量按当前审计修订计数。
- 历史作品成绩不会自动挂到新工程；新工程没有观测时保持零条记录。
- 双击或重复请求返回同一工程。创建中断或关联保存失败时保留工程，复核后明确重试原请求；重启不自动继续创建。
- 已尝试创建的条目不再改变目标和依据，避免把保留工程错挂到新任务。需要新方案时添加新条目或另建内容组。
- 归档后仍能打开工程；不同空间的内容组、证据和作品严格隔离。

本地工具协议和真实资料下的工程创建、编辑、保存与归档流程已验证；真实供应商的成组候选质量尚未验收。
