# 内容观测

在「计划 → 观测与实验」管理当前空间中已有作品的发布关联和观测值。当前支持发布结果关联、CSV 导入、修订审计与观察差异计算；假设编排和下一轮工程任务尚未接入。

## 关联已有发布结果

选择工程，点击「读取已有发布关联」。程序只读取现有发布记录，区分已提交与可信作品回执，保留发布快照版本。导出完成不会计为发布成功。目前自动可信作品网址来自 TikTok Studio 回执；其他平台或历史记录缺少可信作品 ID 时，需要人工核实并补充。

手工补充需要脱敏账号别名、平台作品 ID 和来源说明，网址可选。保存后始终标为「人工声明，未由程序核实发布」，不能提升为可信回执。程序生成的账号别名经过散列；人工数据应对同一账号使用一致的别名。关联本身不会上传、发布或调用模型。

## 导入观测

先建立发布关联，再复制其「发布关联 ID」到 CSV 的 `publicationLinkId` 列。页面可填入空白模板标题，或选择本地 CSV。默认列如下，列名不同时可在字段映射中指定：

```csv
publicationLinkId,metric,definition,unit,value,start,end,timeZone,alignment,ageStartHours,ageEndHours,confounders,sourceNote,observedAt
```

- `metric`：稳定的指标键，如 `likes`。`definition`：完整口径，需注明累计值或窗口新增值，以及数据来自哪里。
- `unit`：`count` 为非负整数，`seconds` 为非负秒数，`ratio` 为 0–1 的比例。
- `start`、`end`：带偏移的 ISO 时间，如 `2026-10-01T00:00:00+08:00`。`timeZone` 使用 `Asia/Shanghai`、`UTC` 等时间区名称。
- `alignment`：`calendar` 比较同一日历窗口；`post-age` 比较发布后相同的时龄窗口。后者必须填写 `ageStartHours`、`ageEndHours`，且时长与起止时间一致；前者留空。
- `confounders`：推广、付费流量、发布时间等干扰因素，用 `|` 分隔，可空。未提供不代表不存在。
- `sourceNote`：真实观测来源和限制，必填。不要把没有窗口依据的公开累计数描述为窗口新增数。
- `observedAt`：实际读取数据的时间，使用带偏移的 ISO 时间，与导入时间分别保留。旧 CSV 没有此列时可将该字段映射留空；旧观测保持时间未知，不能参与差异比较，直到人工补充并保留修订。观测发生时窗口尚未结束的记录也不能用于比较。

CSV 支持引号、逗号和引号内换行，最多 100 万字符、1000 行；界面选择文件另限 1 MB。先预览全部映射结果，修复错误行，再明确确认导入。重复观测不追加；冲突值只有确认修订后才写入新版本，全部旧值保留。导入期间已有观测变化时，必须重新预览。

## 比较与审计

选择对照和变体观测。程序要求两个不同作品的平台、账号别名、指标口径、单位、窗口对齐方式与时间区一致；不满足时显示「不足以判断」。日历窗口必须具有相同起止时间，发布后窗口必须具有相同时龄。

相对变化为 `(变体 − 对照) / 对照`。对照为零或超出可计算数值范围时显示 N/A，不伪造增长率。比较保留已录入的干扰因素，结果只表示观察差异，不能证明因果。查看审计版本可回看旧数值、口径、窗口、来源说明和导入文件摘要。没有观测时不会生成表现结论。

## 本地检查

```bash
pnpm check
pnpm test
pnpm --dir desktop exec vite build
cd desktop
node scripts/content-metrics-electron-qa.cjs /private/tmp/gardenflow-metrics-qa
```

最后一项使用明确标注的合成观测，在隔离 Electron 中验证导入、修订、计算和空间隔离，封锁外部请求。它不代表真实业务表现验收；每次运行须使用新的临时目录。
