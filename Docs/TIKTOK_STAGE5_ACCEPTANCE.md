## 实现范围

- 商品视频工作台创建独立 TikTok 工程，复制镜头、素材、字幕、旁白和音乐，清空旧导出与确认；复用已创建的版本，明确“再复制一版”才新增。
- 独立保存语言、目标市场、内部标题、发布文案、话题和发布设置。手动修改及重开不改变来源、小红书或抖音版本。
- 使用设置中的文本模型提供逐镜头语言建议，支持 OpenAI、Anthropic、Gemini 协议；展示前后字幕和旁白，确认后主进程按建议 ID、空间、稿件 revision 和工程更新时间校验并写入。无效或遗漏镜头、过期建议不应用；无旁白镜头不能由模型自动添加旁白。
- 应用建议不生成视频、图片或语音。旁白文字变化后旧音频标为过期，须单独重新生成、导入或移除，并重新导出最新 MP4。
- 桌面与 Native Host 的发布能力白名单已加入 `tiktok.publish.v1`，只有新版插件显式注册才授予；实际本机桥接测试验证状态／发布转发、旧插件不误授予及采集隔离。平台发布插件提供 `tiktok.publish.v1`，限定 `https://www.tiktok.com/*`。保留原插件 ID、小红书和抖音能力；采集插件继续独立。
- 发布任务绑定真实账号 handle、版本、成片 SHA-256、独立上传文件及所有已确认设置。上传供核对和点击 Post 分开；页面回读不符、其他草稿、错账号、验证、设置不可用会停止。
- 同一任务最多点击一次 Post；已记录发布成功的任务不能用“未发布”恢复覆盖，再次准备仍返回原成功记录。提交之前持久保存未知状态，服务重启不重投。人工核对发布结果单独留档，原账号返回空白上传页后才释放任务归属；插件不会自动 Discard 用户草稿。
- 已核实发布的任务支持单独读取 Studio Posts 的作品回执，保存作品 ID、准确链接、账号、完整文案、可见范围、页面日期／时长与读取时间。主进程再核对任务摘要、当前空间、成片时长和作品 URL；拒绝重复候选、跨账号、跨域、替换已保存的作品及另一任务已经占用的回执。读取不上传、不点击 Post、不修改创作版本。首次提交的未知结果仍需人工核实，不能仅用同文案行推断本次成功。
