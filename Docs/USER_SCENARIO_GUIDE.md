# GardenFlow 新用户场景使用手册

从导入第一份资料，到制作作品、核对发布，再用真实反馈规划下一轮。

适用日期：2026 年 10 月 25 日。本文对应当前源码中的界面与能力；较早安装包可能缺少部分入口。页面中的实际状态、可用模型和确认提示优先。

## 阅读与体验路线

这份手册适合第一次使用 GardenFlow 的内容创作者、商品运营者和个人记录者。按章节操作，可以逐步体验当前主要入口。每个场景都提供目的、入口、操作、示例和完成标志；需要额外服务的环节会说明前提。

主案例是为一只通勤保温杯做内容：整理商品资料，研究消费者顾虑，制作图文和视频，逐项核对发布，再记录表现。文中的“青禾”“通勤杯 A”、示例文案、假设和演算数值均用于练习，不代表真实品牌、消费者评价、商品性能或业务成绩。正式使用时替换为自己有权使用并已核实的资料。

建议分三轮体验，时长只是安排参考，模型等待、下载和平台操作会另行占用时间。

| 轮次 | 阅读范围 | 主要成果 | 所需条件 |
| --- | --- | --- | --- |
| 第一轮 约 30 至 45 分钟 | 第 1 至 4 章、第 7 章 | 一份可重开的文字稿和一套可编辑卡片 | 文本模型可选，手工卡片无需模型 |
| 第二轮 约 60 至 120 分钟 | 第 5 至 6 章、第 8 至 12 章 | 有依据的方向、套图、视频与内容组 | 网页采集需采集插件，AI 步骤需对应模型 |
| 第三轮 分次完成 | 第 13 至 18 章 | 发布核对、真实观测、实验、自动任务与备份 | 发布需账号和发布插件，复盘需真实数据 |

只想体验个人创作，可先做第 4、7、10、11 章。没有真实发布需要时，第 13 章进行到上传前即可；不会因此影响本地创作。

### 先认清四种东西

**资料**是收集的原文、商品快照、评论和本地文件。**作品工程**保存可编辑的文字、页面或分镜。**导出文件**是 PNG、ZIP、MP4 等可交付结果。**发布任务**记录面向某个平台和账号的上传、核对与提交状态。保存工程后仍需导出；导出完成后仍需准备和核对发布。

**空间**用于区分不同品牌或项目；**工作空间目录**是本机保存文件的位置。切换空间与更换本机目录是两件事。

### 在哪里找到功能

点击左侧一级入口后会展开其子页面。进入作品编辑时全局导航会收起，用顶部返回入口回到“我的作品”。窗口较窄时先打开导航菜单。

| 一级入口 | 当前子页面 | 本手册对应章节 |
| --- | --- | --- |
| 工作台 | 继续工作、待处理 | 2、16 |
| 研究与选题 | 消费者机会、消费者研究、灵感选题、来源复核 | 5、6、17 |
| 创作 | 我的作品、成组内容、AI 助手、生成工具 | 4、7 至 12 |
| 发布 | 发布任务、发布历史、账号与连接 | 13 |
| 复盘 | 作品表现、内容实验 | 14 |
| 资源库 | 资料、商品与品牌、角色与声音、媒体、风格档案 | 3、4、10、15 |
| 自动化 | 自动任务、运行记录、待确认 | 16 |
| 设置 | 通用、AI 服务、连接、技能、成员、隐私与诊断 | 1、3、15、18 |

## 1 安装并准备第一次使用

### 场景 我要先确认产品能用 再逐步增加服务

**入口：**首次启动，以及“设置 → 通用”“设置 → AI 服务”。

1. 从项目发行页下载与系统架构匹配的安装包。Apple Silicon Mac 使用 arm64，Intel Mac 使用 x64，Windows 使用 x64 exe，Linux x64 使用 AppImage 或 deb。安装包的签名与系统提示处理见[安装说明](./PACKAGING.md)。
2. 打开 GardenFlow。进入“设置 → 通用”，确认“工作空间目录”；点击“打开”查看位置。第一次可保留默认值，不要把改路径当成自动迁移或备份操作。
3. 在左侧空间菜单点击“创建空间”，命名为“通勤杯内容练习”。后续在这个空间导入资料、建工程。另建空间“个人故事”，供梦境场景使用；做完后切回主空间。
4. 若要使用 AI，进入“设置 → AI 服务”，点击“添加供应商”或空页面的“添加第一个供应商”。选择服务对应预设，填写 Endpoint、API Key 和默认模型。已运行的本地兼容服务使用其真实本机地址，Key 可留空。
5. 展开“能力路由”中的“内容创作”，选择“自定义”，指定供应商和模型，点击页面底部“保存设置”。普通对话与团队分别有“对话”“团队协作”路由；需要消费者研究时再设置“灵感选题”。图片、音频、转录和语义检索也要分别设置对应能力。
6. 到“创作 → AI 助手”发送：“请只回复一句话，说明你已经收到这条测试消息。”先检查普通文本能否正常返回，再尝试带工具或附件的任务。

**完成标志：**空间名称正确；设置显示已保存；文本请求有实际回复。供应商的“可用”标记只表示配置完整，还要用实际请求检查网络、额度和模型能力。

**没有模型时：**仍可管理本地资料、手工整理机会、编辑卡片和管理媒体。需要 AI 的步骤保留到配置完成后再做。GardenFlow 不提供共享密钥或官方模型余额；外部服务费用由所选供应商收取。

**视频设置补充：**“AI 服务”下的视频供应商需要单独选择类型、Endpoint、Key、模型及启用状态。New API 要明确选择阿里云或 MiniMax 上游。用商品原图做动效视频，可先关闭视频生成服务。

## 2 熟悉工作台与作品管理

### 场景 我昨天做了一半 今天想接着编辑

**入口：**“工作台 → 继续工作”“创作 → 我的作品”。

1. 首次进入工作台，可点“开始创作”“研究消费者”或“导入资料”。没有作品时点击“创建第一件作品”。
2. 创建过作品后，首页“继续创作”展示最近可用作品。点击作品卡进入原作品；右侧“待处理”会列出需要检查的文件、等待确认的操作和需要核实的发布事项。
3. 打开“我的作品”，按标题搜索，按形式和平台筛选，切换画廊或列表，并选择“最近编辑”或“作品名称”排序。
4. 如果看不到作品，先清除筛选，再核对当前空间，必要时刷新。出现文件缺失或目录部分加载提示时，按提示检查原文件；不要立即新建同名工程代替原作。
5. 进入编辑器后，用顶部返回入口回到作品目录。需要另做方案时使用“另建版本”，并检查新版本的平台、文案、素材和对话。

**完成标志：**能从目录重新打开同一作品，看到上次保存内容及对应对话。列表卡片、聊天里一句“已完成”和磁盘中的真实文件应分别核对。

**常用操作：**侧栏“开始创作”打开创作选择器；Mac 使用 Command 加 N，Windows 和 Linux 使用 Ctrl 加 N。顶部搜索用于找资料，通知入口用于看任务提示，主题按钮可切换明暗外观。“设置 → 通用 → 重新打开产品引导”可重看引导。

## 3 建立商品资料并连接浏览器

### 场景 我要围绕同一只杯子反复创作

**入口：**“资源库 → 商品与品牌”“设置 → 连接”。

**先用手工资料练习。**新建品牌“青禾”，描述“服务通勤人群，表达简洁，强调使用场景”。在该品牌下新建“通勤杯 A”，描述填写“练习用商品，容量与材质待核实”，受众填写“希望减少随身物品的上班族”，场景填写“通勤、办公室”。上传自己拍摄或有权使用的商品图，按需添加 SKU。没有来源证实前，不填具体保温时长、防漏承诺或虚构价格。

**再采集真实商品。**这部分需要已登录的平台浏览器与采集插件。

1. 到“设置 → 连接”的“浏览器插件”点击“准备插件”，再点击“打开插件目录”。
2. 在 Chrome、Edge 或 Brave 的扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，加载应用导出的采集扩展目录。保持 GardenFlow 打开，并检查插件已连接。仅“已准备”还不等于握手连接成功。
3. 打开你准备研究的京东、淘宝或天猫桌面商品详情页，先选中目标颜色、容量等规格，展开商品详情和评价，等待图片加载。
4. 打开采集扩展侧栏，点击“预览商品资料”。核对名称、平台、店铺、所选规格、价格条件、参数、主图与详情图。缺失时先在网页展开相应区域，再点“重新识别”。
5. 淘宝或天猫练习先采当前评价列表 5 条；若选择标签，使用页面真实存在的标签，每个标签可设 1 至 50 条。默认数量和可用选项以当前插件为准。
6. 确认后点击“确认保存到资产库”。回到“资源库 → 商品与品牌”，在品牌或“待整理商品”找到它，核对来源和图片。网页采集商品与手工练习商品可能是两个独立条目，创作时选清楚。

**完成标志：**商品详情存在可查看的来源快照，含采集时间、当前规格与实际取得的内容；缺失项有明确提示。价格是当时页面快照，不能当成长期售价；评论是采样，不能当成全部买家意见。

### 场景 商品信息更新 或在另一平台看到同款

同平台同商品重采会追加快照，保留已有手工编辑；可在商品详情按时间与规格切换。另一平台的商品独立保存。使用“AI 查找同款”查看候选与依据，确认后点“确认关联”；没有模型时可“手动选择商品”。同款关联不会合并两个商品的素材，创作中选择哪个商品，就引用哪个商品的资料。

登录、验证或访问限制出现时，在原网页处理后再重试。部分采集会保留已读资料；页面上没读到评论不等于没有评论。硬删除商品会永久删除相关资料、快照、SKU、评论和本地图片，练习时也应先核对对象。

## 4 导入资料并写出第一篇稿件

### 场景 我想先完成一个不依赖网页的完整任务

**入口：**“资源库 → 资料”“创作 → AI 助手”。需要文本模型；本地导入本身不需要浏览器扩展。

1. 下载仓库提供的[公开示例资料](../examples/first-creation/sources/gardenflow-facts.md)，保存为 Markdown 文件。
2. 在“资源库 → 资料”点击“添加文件”，选择它。资料页也提供“添加文件夹”；第一次先导入单个文件。打开条目确认原文完整，查看索引状态。
3. 用全文搜索查找“本地”或资料中的其他词。未配置 Embedding 时，先用全文搜索和明确选择来源；语义相似度检索需要单独的 Embedding 配置。
4. 到“AI 助手”新建会话，用 `#` 或来源选择器选中刚导入的资料，确认输入区出现来源后发送下面的要求。

**示例输入：**

> 根据所选资料，为第一次接触 GardenFlow 的创作者写一篇约 600 字介绍。先给我三个角度，说明每个角度的读者问题和可引用来源。不要编造用户量、效率提升或亲身使用体验。

5. 选择一个方向，再发送：“采用第二个角度。写出正文，保留能回到原文的来源，清楚说明需要自行配置模型。请将核对后的结果保存成可再次编辑的稿件。”
6. 检查任务时间线的模型与工具状态，遇到写入确认时核对目标文件。打开保存后的稿件并修改一句话，离开后重新打开。

**完成标志：**稿件正文真实存在，修改仍保留，来源可以回看。AI 只在聊天中给出正文时，继续要求保存；也可使用稿件的新建入口人工保存，随后重新打开检查。

### 场景 我还想收集一篇文章或一条短视频

浏览器中打开文章，使用采集侧栏的通用网页采集，预览正文与来源后保存；小红书列表、笔记和评论使用相应结构化采集入口。保存后到“资源库 → 资料”核对，而非只看浏览器成功提示。

抖音或国际 TikTok 的视频与图集，在详情页使用“保存视频”或“保存图集”；也可在资料页用“链接采集”粘贴作品链接或分享文本。评论默认 5 条，可设 0 至 200；0 只关闭本轮采样。短链解析依赖已连接浏览器，目标作品切换时会停止。

打开保存结果，检查本地视频能否播放、图集顺序、文案和评论。“部分保存”时查看缺失原因，再用“重试补采”补充同一条资料。转写依赖独立的转录配置，转写失败不会清空已保存视频。YouTube 页面也有保存入口，具体取得内容以结果为准。

**费用提示：**资料页的“图像理解索引”开启后，会分析新图片、PDF 页面截图及图文素材，调用视觉模型并产生额外消耗。普通全文搜索无需为了体验而开启它。

## 5 从评论发现消费者问题

### 场景 我想知道消费者为什么犹豫买这只杯子

**入口：**“研究与选题 → 消费者研究”。需要已有来源；AI 分析使用设置中的灵感文本模型。

1. 勾选一两个真实商品快照或已有文档，先用小范围体验。不要把手工练习文案标成真实消费者评论。
2. 填研究目标：“找出通勤人群在携带、清洗和容量选择上的顾虑，保留支持、反例及缺少的资料。”选择本轮评论上限。
3. 点击“预览本轮范围与模型”。核对来源名称、版本、采集时间、实际样本数量、片段和字符数、部分采集限制及模型主机。展开“查看本轮将发送的原文”。
4. 勾选发送原文与可能费用的确认项，再点“确认并运行分析”。更改来源或模型后重新预览。
5. 检查候选里的消费者问题、受众、内容角度、支持和反例。打开引用，比较是否与原文一致。

**示例理解：**如果真实样本确实有人提到清洗杯盖麻烦，可以考虑“通勤杯清洗前先看哪些结构”。如果资料里没有这句话，把它作为待验证想法记录，不能给它编一个评论来源。

**完成标志：**候选有可定位依据及明确限制，或者系统明确返回没有足够可信的机会。返回 0 项也可能是合理结果。模型评分是主观排序依据，不是成功概率；少量评论不能推出全平台消费者比例。

分析失败、取消或应用中断后不会自动补发；重试需重新预览确认。相同范围与模型的已有结果可能复用。当前单轮最多选择 20 个来源；来源过多时缩小范围。

## 6 整理机会并形成创作方向

### 场景 我已有一个想法 想先把依据整理清楚

**入口：**“研究与选题 → 消费者机会”。手工整理无需模型。

1. 首次打开可选择“已有想法，手动记录”；已有列表时通过“更多 → 手动新建机会”。
2. 标题填写“通勤杯清洗结构说明”，问题填写“购买前不知道哪些部位容易清洗”，受众填写“每天带杯上班的人”，角度填写“通过结构展示帮助读者自查”。这些都是练习假设，先保持待验证。
3. 展开“添加来源依据”，选择入库来源和原文片段，标为支持、反例或背景，点击“绑定这条原文”。有多个来源时分别绑定；缩短引用时保留连续原文。
4. 保存后进入详情，点“打开原始来源与定位”，检查历史版本。没有支持证据时，保留待验证假设状态。
5. 有合适依据后点击“基于此创作”，选择平台和形式，再点“采纳并创建作品”。商品视频、混剪或套图需要证据中明确的商品；多个商品时选择本次使用哪个。
6. 在新作品展开“创作依据”，核对机会与反例是否跟随进入。关闭选择弹窗不会创建作品。

**完成标志：**从一项机会打开其关联作品，并能返回证据。创建工程只是得到本地草稿；后续生成、上传和发布各自确认。

### 场景 我想探索几个选题 再决定做哪一个

进入“研究与选题 → 灵感选题”，选择来源范围或素材，运行灵感漫步或当前可用的评论洞察。比较标题、方向、证据与评分，放弃不合适的候选；选中方向后用“AI 创作”带入创作。与消费者研究一样，先看样本和事实，再把结果当作候选角度。

## 7 把文章变成可编辑图文卡片

### 场景 我想把第一篇介绍稿做成六张小红书卡片

**入口：**“开始创作 → 图文笔记 → 继续”，选择小红书；也可从“我的作品 → 新建作品”进入。文本初稿需文本模型，手工编辑与导出无需模型。

1. 在“创作方式”选择文章转卡片，加入第 4 章保存的文字稿或公开示例资料。也可选择自由创作、知识图解或步骤教程；文章来源可以和图解或教程组合。
2. 读者填写“第一次接触 AI 创作工具的人”，要求填写“六张以内，一页讲一件事，不编造产品成绩，保留配置前提”。
3. 使用“生成初稿”或在作品对话发送：“将所选文章拆成封面、资料导入、带来源写作、可选封面、常见问题和总结六页。先使用可编辑文字和模板，不生成配图。”
4. 在左侧逐页选择，中央检查预览，右侧切换“属性”“AI 助手”和“创作上下文”。按内容选择封面、标题正文、图文分栏、对比、步骤或总结清单模板。
5. 手动改第二页标题；再让 AI “把当前页改成三步操作，每步不超过两句话”。核对实际页面变化，必要时撤销。需要重组内容时先看候选差异再应用。
6. 先导出当前页 PNG，检查可读性；再导出整套目录或 ZIP。默认 3:4、1440×1920，整套包含图片、发布文案和作品清单。

**完成标志：**文字仍可在工程内编辑，导出的 PNG 能打开且没有溢出，整套页序正确。普通图文卡片当前需在平台手动上传；商品套图的发布流程见第 8、13 章。

**文章来源限制：**支持 Markdown、TXT、文本型 PDF、DOCX、知识文档、已收藏文章和文本稿件。扫描 PDF 先做 OCR，旧 `.doc` 先转 DOCX。源文更新会提示版本变化，点击“重新读取”加入新版本；已有卡片不会自动重写。

**没有 AI 时：**新建页面、选模板、粘贴自己的正文、手工排版并导出，仍可完成这个场景。生成配图需要另行核对图片模型。

## 8 为商品制作一套小红书图片

### 场景 我想说明杯子的外观 细节与购买前核对项

**入口：**“开始创作 → 商品套图”，选择小红书；已有商品也可在 AI 助手用 `@` 选商品，再点“商品创作”。

1. 选定真实商品与具体 SKU，检查工程引用的图片。练习时可用手工商品和自有图片，但所有文案保持“练习用，事实待核实”。
2. 要求填写：“面向通勤人群做五张图：封面、携带场景、杯盖结构、规格选择、购买前核对。只使用已核实字段；缺少的事实写成待核实问题。”
3. 新入口可先保存空白草稿，再补商品、页面与图片，填写完整后点“继续制作”。使用商品快捷入口时，先选目标并“按此目标规划”，核对方案后创建工程。文本规划可能产生费用。
4. 核对每页的商品规格、素材缩略图、文字和布局。默认五张含封面，3:4、1440×1920 PNG。封面固定第一张，内容页可增删排序，最多编辑 20 张。
5. 试着把第三页换成多图细节模板，调整裁切、颜色与字号；让对话“缩短第三页文字，不改变商品事实”，检查改动。
6. 默认可使用商品原图。若某页需要 AI 画面，逐页核对生成请求，再确认；标题和文案仍是本地可编辑文字层。
7. 导出单页检查后，再导出整套目录或 ZIP。修改页面后更新导出，系统可复用未变页面的有效图片。

**完成标志：**封面在第一张，全部页面均有有效图片，文字无溢出，工程能重开，整套文件可用。准备平台发布前控制在 18 张以内，这是应用的发布限制；19 或 20 张工程可导出，但须自行减少页数才能发布。

抖音和 TikTok 商品套图当前待适配，不能按同一流程创建。迟到的旧生成结果会保留为素材，需核对后再使用。

## 9 制作商品视频 混剪与视频笔记

### 场景 我想把商品原图做成一条十五秒短视频

**入口：**“开始创作 → 商品视频”。支持小红书、抖音和国际 TikTok；默认可用原图动效，不需要视频生成模型。

1. 选择平台、真实商品、规格、语言与市场，明确“商品原图编排”。默认 15 秒、9:16、1080×1920、30fps；小红书还可选 16:9。
2. 示例要求：“做三个镜头，各五秒。先展示通勤场景，再看杯盖细节，最后提醒读者核对容量和尺寸。不写未经验证的保温或防漏承诺。”
3. 补充分镜与实际素材，核对后“继续制作”或确认方案创建工程。视频最多 8 个镜头，每镜头最多 30 秒。
4. 在预览下方时间线试着调整顺序、时长和动效；改一条字幕，再用对话要求“把第二个镜头缩短一秒”。检查总时长与字幕是否仍合适。
5. 添加自己的 BGM 或已取得的旁白，分别调整原音、旁白和音乐音量。旁白长于镜头时，缩短文案或延长镜头。
6. 预览后点击“保存 MP4 到资产库”或当前导出入口；到“资源库 → 媒体”播放实际 MP4，检查开头、结尾、字幕、声音与画幅。

**完成标志：**有真实可播放 MP4，且与最新工程一致。改旁白后旧配音会过期，需重新合成或明确移除；无配音素材的商品工程可静音导出。改了画面或音轨后必须重新导出。

### 场景 我有三段自己拍摄的视频 想剪成另一版

选择“开始创作 → 视频混剪”，选择当前空间已有片段，或通过素材入口导入自己的视频。为每段设置截取起止、画幅适配和音量，核对顺序，再导出。原音、旁白和 BGM 分别控制，不能仅凭某段预览无声就判断全片静音。

### 场景 我想做一条小红书知识视频

选择“视频笔记”，当前支持小红书。先写标题、发布正文、分镜和旁白，选择实际图片或视频素材；在工作台完成编辑、预览和视频导出。可把第 7 章的“资料导入三步”改成视频脚本。素材不足时先补齐，聊天中的分镜文字不代表已经生成视频；发布能力以该作品显示的实际入口为准。

### 场景 同一商品还需要抖音和英文 TikTok 版本

在商品工程中使用“创建抖音版本”“创建 TikTok 版本”或“创建其他平台版本”，生成独立副本。再次点击通常打开已有目标版本，“再复制一版”才新增。修改副本后检查来源工程仍是原内容。

抖音版在“抖音稿件”编辑描述、话题与封面。自选封面会从工程素材生成竖横两种裁切，发布时核对实际封面；安全区阴影只是排版提示。

TikTok 版在“TikTok · 文案与语言”设置语言代码和目标市场；内部标题不等于平台文案。可用“AI 语言建议”先看字幕、旁白的前后对照，确认后应用；它不自动生成新配音。文案和话题合计最多 4000 字符。分别保存、导出各版本，生成与发布需要各自确认。

## 10 单独生成图片 封面 声音与视频

### 场景 我只缺一张封面 或一段可复用旁白

**入口：**“创作 → 生成工具”。可见工具包括“生图”“做封面”“生视频”“生音频”；实际选项由模型能力决定。

**图片练习：**选“生图”，添加有权使用的参考图，输入“清晨通勤桌面，杯子旁有笔记本，柔和自然光，不添加商品性能文字”。先选一张、3:4，核对模型、规格与费用后生成。产品外观由 AI 改写时，不能当作真实商品照片直接使用。

**封面练习：**选“做封面”，选择已保存稿件或参考图，输入标题“从资料到第一篇稿件”，调整当前支持的字体、色彩或换景选项。打开结果，检查文字与画面；需要保持文字可编辑时，回卡片或套图工程编辑文字层。

**声音练习：**选“生音频”，输入“出门前，先确认今天需要的容量，再检查杯盖是否合好。”选择已配置模型、兼容音色、语速和情绪，先做短样本。试听发音、停顿和响度，再应用到作品。音色能否使用取决于供应商与模型的匹配。

**视频练习：**选“生视频”，按照当前模型开放的文生视频、参考图视频、首尾帧或续写模式添加输入。先用允许的最短时长试一个镜头；支持参考音频与否、尺寸、清晰度和秒数以界面能力约束为准。

每项任务提交前核对供应商、模型、参考素材和请求数量。停止任务不保证能撤回已提交的外部调用或费用。失败或结果未知时先查任务与供应商状态，再决定重试。

**完成标志：**结果已写入真实文件，并能在“资源库 → 媒体”预览。媒体页可搜索、筛选、定位文件，并把结果复用为参考或放入作品素材槽位。生成记录清理和磁盘文件删除应按各自界面的说明操作。

**进阶入口：**数字人口播需要角色参考视频和兼容音色。当前生成工具主界面提供上述四类工具；只有在版本明确提供数字人入口时，才按第 15 章完成角色就绪检查后尝试短文案。

## 11 把一个梦做成八幕故事

### 场景 我想做一个与商品无关的个人短片

**入口：**先切到“个人故事”空间，再“开始创作 → 梦境故事”。记录与手工编辑不调用模型；文本和媒体生成按所用服务计费。

1. 输入：“我在夜间车站等车，站牌上的目的地变成了童年家的地址。列车进站时，车窗里坐着小时候的自己。”保存原始记录。在“记录与版本”补日期、情绪和偏好，按需锁定原句。
2. 核对 TikTok Studio 目标、语言和市场。新工程默认混合模式、英文、International、72 秒、旁白和字幕；目标可选 60 至 90 秒，固定 9:16、1080×1920、30fps。
3. 对话要求：“保留原始三句话作为记录，把它扩成有起承转合的八幕故事。新增情节标清创作补写，先给分镜，不生成媒体。”也可展开“手动编写故事与八幕分镜”。
4. 核对每幕画面、旁白、时长和顺序。在“故事”调整画风与角色。建议第一轮选全图片模式，导入自己的图片或逐幕生成图片，配合运镜体验完整流程。
5. 在“人物与场景基准”固定反复出现的人物和地点；需要时本地裁切参考。先试一幕，确认后沿用基准。连续镜头核对前幕参考，切换地点时选择“切场”。
6. 逐幕制作或导入声音，试听并检查实测时长。旁白文字变化后重新处理声音。可展开“连续性复核（不生成）”检查登记的关系与空间约束；它不能代替肉眼检查画面。
7. 确认各幕关键帧与需要的视频，先导出低清预览，再导出正式 MP4。缺旁白时补声音，或明确关闭旁白；不会静默当成有声成片。

**完成标志：**八幕完整，人物与场景能连续理解，字幕和声音对应，正式视频真实可播。全视频与混合模式还需逐幕核对视频请求；素材时长不足时调整计划，不能假定系统会循环补足。

**导出与隐私：**可导出故事 Markdown、导演包 JSON、SRT、MP4 和 ZIP。分享默认排除原始记录、历史及内部提示；完整备份和私密内容选项要单独核对。原始梦境默认留在工程范围，外部生成仍会发送该次所需内容。本地保存不等于已加密。

**旧项目：**导入入口接受支持的旧导演包 JSON；先核对缺失项再创建新作品，旧媒体需手动匹配。ZIP 是快照，当前没有 ZIP 一键恢复。修改制作模式、语言或市场会建立独立版本；新版本重新核对媒体和授权。

## 12 围绕目标组织成组内容

### 场景 我准备做三篇内容 分别回答三个购买前问题

**入口：**“创作 → 成组内容”。先有已采纳、依据可核对的消费者机会。当前为开发版能力，先体验小组。

1. 点击“新建内容组”，命名“通勤杯选择指南”，填目标“帮助读者核对是否适合自己”，选择受众、商品、平台和已采纳机会，写入“不得添加未核实性能”限制。
2. 点击“核对规划依据”，检查来源版本、证据和商品素材。目录里有一项素材记录，还要检查真实文件能否使用。
3. 手工添加至少三条、不同职责的内容：认知“通勤前先想三个问题”、教育“如何核对容量与尺寸”、顾虑解答“购买前问清杯盖如何清洗”。每条依据必须来自所选机会。
4. 想借助模型时点“去对话规划（先填草稿）”，检查草稿后自己发送。模型提出的列表先复核，不会直接生成成片。每组最多 8 条，依赖只指向前面的条目，用于策划顺序。
5. 确认当前列表，勾选并确认创建其中一条，进入独立工程。在“成组内容任务”和“创作依据”中核对职责与限制，再制作作品。
6. 列表变更后重新确认；逐条编辑、生成与发布。做完可归档内容组，已有工程和历史仍保留。

**完成标志：**内容组包含有分工的条目，每条能进入自己的工程；不会把“已规划”误认成“已完成”或“已发布”。该入口不提供批量最终发布。

## 13 核对账号并逐步发布

### 场景 我已导出作品 想确认每一步会做什么

**入口：**作品中的“准备发布”，以及“发布 → 账号与连接”“发布任务”“发布历史”。需要平台账号和独立的发布插件。

1. 应用启动时会准备采集与发布两套扩展。到“设置 → 连接”点击“准备插件”和“打开插件目录”；打开的是采集目录 `gardenflow-capture`，在文件管理器返回上一级，选择同级的 `gardenflow-xhs-publisher` 目录，在浏览器扩展管理页加载它。虽然目录名含 xhs，它是当前支持小红书、抖音和 TikTok 的平台发布插件。更新后重新加载；若同级目录缺失，先更新并重启桌面端，再检查。采集插件与发布插件分开，采集已连接不代表发布可用。
2. 在浏览器登录目标平台的创作者或 Studio 上传页，保留一个本次使用的上传页面。在“发布 → 账号与连接”刷新状态，核对平台真实账号，点击“绑定此浏览器”。
3. 回到作品，保存当前编辑，确认最新 MP4 或整套图片有效。填写发布正文、话题、封面与平台设置。TikTok 的可见范围、评论、内容复用、Remix、商业披露、AI 标记和年龄限制需完整选择。
4. 点击“准备发布”。确认卡应显示正确作品、媒体、账号、浏览器、文案和设置。这一步只创建本地任务。
5. 点击“上传到页面供核对”或该平台对应上传按钮。到真实页面检查视频或图片顺序、完整文案、封面和设置，并等待程序回读检查。
6. 所有内容准确且确实准备公开时，再点击平台对应最终确认按钮。仅体验流程时，可在提交前停下并保留草稿；对话里回复“发布”不能代替按钮确认。
7. 在“发布任务”或“发布历史”点“查看任务与回执”，核对真实提交状态。有可信作品链接时再打开平台作品核对。

| 阶段 | 会发生什么 | 本阶段要检查 |
| --- | --- | --- |
| 准备发布 | 建立本地任务并读取目标 | 当前工程、导出媒体、账号与设置 |
| 上传供核对 | 上传媒体并填入平台编辑页 | 实际页面与回读结果是否一致 |
| 最终提交 | 明确确认后请求平台发布 | 同一账号、同一作品、最新核对仍有效 |
| 查看结果 | 保存提交状态及可取得的回执 | 是否审核中、结果未知或已取得可信链接 |

**完成标志：**平台结果和桌面记录相符。上传成功、已经提交、审核中、人工核实已发布和可信回执各有含义；不要仅凭按钮执行完就认定公开成功。

### 遇到阻断时怎样处理

**已有其他草稿：**先在平台人工核对，包括“继续编辑上次未发布的视频”提示。插件不会代为丢弃或覆盖。

**修改过工程、文案、账号、浏览器或页面：**旧确认失效，重新准备或按提示重新核对。画面与声音变化还要更新导出。只有描述变化时可能复用媒体，但仍需重新确认发布。

**抖音封面失败：**原任务会保留视频和文案。先核对并关闭封面弹窗，再从原任务重试上传核对；不要忽略封面错误。

**TikTok 梦境封面变化：**在 Studio 人工确认实际封面，避免淡入黑帧。若确实只改封面，可在面板明确确认“仅修改封面”，使用“重新核对封面（不上传）”；无法保证未改其他内容时重新核对完整任务。

**提交结果未知或审核中：**先到原账号作品管理核实，按桌面任务提示记录已发布或核实未发布。原浏览器可能需要回到空白上传页后才能完成记录。已提交、结果未知和审核中的任务不直接重发。

**TikTok 回执：**人工核实后可在 Studio Posts 页面“读取已发布作品回执”。账号、文案等信息不能唯一匹配时会停止；人工声明不会自动变成可信回执。真实审核及拒绝分支的验证范围见[路线图](../ROADMAP.md)。

**完成后提醒：**“发布 → 账号与连接”可按平台开启“完成后询问是否发布”。它只对之后的新完整导出发出询问，单页 PNG 不触发；不开启自动上传或最终提交。

## 14 记录表现并设计下一轮实验

### 场景 我有两条真实作品 想比较不同开头的表现

**入口：**“复盘 → 作品表现”“复盘 → 内容实验”。手工记录和计算无需模型。

1. 在“作品表现”选择工程，点“读取已有发布关联”。程序区分提交记录与可信回执；缺少可信作品标识时，可人工补充脱敏账号别名、平台作品 ID 和来源说明。人工记录始终保留未由程序核实的标记。
2. 只有历史链接而没有原工程时，用“记录历史作品链接（未关联原工程）”。不要建一个空工程冒充原作；该记录保持版本未知。
3. 建立关联后复制“发布关联 ID”，展开观测导入，使用页面空白模板或选择本地 CSV。按真实后台字段映射，点击预览，先修复错误，再确认导入。
4. 对两条作品选择同口径观测，检查平台、账号、指标定义、单位、窗口和时间区。重复数据不追加；同一观测冲突值需确认修订，旧值保留。

**一行怎么填：**`publicationLinkId` 用刚复制的真实 ID；`metric` 可为 `likes`；`definition` 要明确是累计点赞还是窗口新增；`unit` 为 `count`、`seconds` 或 `ratio`；`value` 用真实数值。`sourceNote` 说明后台位置与限制，`observedAt` 填实际读取时间。

**时间练习：**若真实统计确为北京时间 2026 年 10 月 20 日全天的新增数，可填 `start=2026-10-20T00:00:00+08:00`、`end=2026-10-21T00:00:00+08:00`、`timeZone=Asia/Shanghai`、`alignment=calendar`。若后台只有日期且时间区未知，填 `unknown`、日期值和 `calendar`，保留不可比较限制。不能从平台语言推断时间区。

CSV 的完整列为 `publicationLinkId,metric,definition,unit,value,start,end,timeZone,alignment,ageStartHours,ageEndHours,confounders,sourceNote,observedAt`。文件最多 1 MB、1000 行；比例用 0 至 1，小数百分比先换算。与发布后相同时龄比较时，用 `post-age` 并填两个时龄字段，且与起止窗口时长一致。详细定义见[内容观测与实验](./CONTENT_EXPERIMENTS.md)。

**演算示例：**在全部比较条件成立时，100 与 120 的相对差异为 20%。这只是算法说明，不是真实成绩；公开累计点赞不能直接冒充某个时间窗口新增。对照为零显示 N/A；口径不一致或版本未知可能显示“不足以判断”。

### 场景 我想只改视频的第一句 再做一次尝试

1. 在“内容实验”点击“新建实验”，写假设：“在相同统计口径下，用具体问题开头的版本可能获得更多互动。”选择对照与变体工程，说明变量、指标和限制。
2. 预览工程版本并确认保存；分别选择真实观测并确认绑定。后来修订观测不会静默改写已冻结的实验报告。
3. 在“规划下一轮单变量编辑”中选来源工程，写修改前后：“今天介绍一个杯子”改为“你的通勤包里还放得下一只杯子吗”，理由为“先呈现使用问题”，列明其余镜头、时长和文案保持不变。
4. 核对来源版本，保存任务，再勾选确认建立副本。进入副本查看“实验编辑任务”，手工或通过对话完成实际修改，再独立导出、发布。
5. 需要 AI 解释时，展开“解释观测与提议下一轮”，预览冻结数据与模型，确认费用后运行。建议只作为待复核草稿，不自动改稿或证明因果。

**完成标志：**旧工程保留，新副本真实存在且改动符合单一变量；实验记录能说明比较什么和哪些条件未知。复制工程本身不会执行那句文案修改，也不会自动生成和发布。真实数据尚未取得时，先完成关联和假设，等待真实窗口结束后再导入。

## 15 建立可复用的风格 角色 成员与技能

### 场景 我希望之后的内容表达一致

**入口：**“资源库 → 风格档案”。

创建“青禾通勤内容”，填写平台“小红书”、领域“通勤用品”、目标“帮助读者做购买前核对”、读者“带杯上班的人”、风格词“简洁、具体、少形容词”。用“导入样本”加入自己有权使用的代表内容，检查样本详情。创作时通过可用选择器引用；没有显式带入时，把已核对的风格要求写进本次需求，不假定建档后会全局自动生效。

**完成标志：**档案与样本保存后可重开，下次作品中能核对实际使用的要求。当前支持手工管理，自动账号学习尚未接入。

### 场景 我想让同一角色与声音反复出场

**入口：**“资源库 → 角色与声音”。角色是作品中的形象素材，与设置里的 AI 成员不同。

新建角色“通勤讲解员”，填写外观、标签和结构化属性，上传有权使用的角色图。可录制或导入声音参考；当前界面要求参考长于 30 秒、文件不超过 10 MB。先保存参考，再按界面核对兼容的 TTS 模型与声音复刻操作。角色视频限制与当前提示一致，当前上传上限 200 MB。

上传角色参考视频可能触发抽取音轨及声音复刻，先核对所用服务与费用。需要数字人时，检查角色参考视频和兼容声音都已就绪，再使用版本提供的数字人入口。生成角色卡、声音复刻和口播结果都需要分别核对，不以“已上传参考”替代“已取得结果”。仅使用自己或已获授权的形象与声音。

### 场景 我想让一个 AI 成员专门检查事实

**入口：**“设置 → 成员”。

点击“添加成员”，名称“事实核对员”，职责“依据已选来源检查商品文案”，角色指令填写：“逐条列出事实主张、来源位置、缺口与建议改写；缺乏证据时标为待核实，不补造体验。”选择知识语言，并用“添加文件”加入 Markdown 或文本资料。

在 AI 助手的“会话与稿件”抽屉使用当前可用的成员或团队会话入口，选择该成员，再发送：“检查这篇稿件，把没有来源支持的保温、防漏与用户体验说法列出来。”核对成员使用的资料与实际回复。成员是本地 AI 角色配置，不是邀请真实协作者的账号功能。

要体验团队，再创建“表达编辑”成员，职责为“按给定事实改善可读性”。在“会话与稿件”的“团队”区域点击“创建团队”，命名“通勤内容小组”，选中这两位成员后创建。先配置“团队协作”模型路由，再发起“共同检查这份稿件，先指出事实缺口，再提出表达建议”的任务，查看团队工作台的过程与结果。团队输出仍要核实；无需创建团队也能完成普通创作。

### 场景 我有一套每次都要复用的写作步骤

**入口：**“设置 → 技能”。

点击“新建”，填写名称“购买前核对稿”。创建后选中技能，点击“编辑”，在 Markdown 中补充用途“把来源事实写成可核对的选择说明”，并填写步骤：“先列来源事实与缺口；再写适用场景；最后给核对清单。不得从商品名推断性能，不编造消费者评价。”保留技能所需的原有字段，保存并检查已启用。

在 AI 助手输入 `@`，从 Skills 区域选择该技能，结合选定商品与来源发起任务。检查任务是否实际使用了技能；技能提供工作原则，仍需相应模型和工具能力。可按需禁用并重新启用，不把保存技能当成已运行任务。

## 16 创建自动任务并处理待确认事项

### 场景 我想每天少量补充通勤杯资料

**入口：**“自动化 → 自动任务”。首次先手动跑一轮，再决定是否定时。

1. 展开内置任务，选择“京东商品自动采集”“淘宝商品自动采集”或“天猫商品自动采集”。准备已登录浏览器及采集插件，填写关键词“通勤保温杯”，第一轮目标新增数设为 1，按需选择保守节奏。
2. 核对评论范围。淘宝、天猫默认读取当前评价列表 5 条，指定真实标签时每标签 1 至 50；京东标签留空时使用其默认好中差范围。任务不调用文本或媒体生成模型。
3. 配置就绪后点“立即运行”，暂时保留定时开关关闭。任务固定保存到启动时的空间，运行中切换空间不会改本轮保存位置。
4. 在任务卡点“查看采集报告”，到“运行记录”看当前状态及各任务最近一轮；通过“查看执行过程”进入关联报告。检查新增、重复、部分保存与失败原因。
5. 确认结果合适后，再设置时间并打开定时开关。桌面端与浏览器需保持运行，退出或休眠期间不能依靠它继续采集。

抖音和 TikTok 自动采集分别配置关键词、频率、评论数、节奏和目标新增作品数；默认 5、范围 1 至 20。每轮轮换一个关键词，有候选尝试上限；重复、更新和部分保存不计完整新增。它不覆盖直播或博主主页整库采集。小红书也有内置采集任务，按当前任务卡配置并查看专用报告。

**完成标志：**报告中的完整新增与实际入库结果相符，零新增、部分完成和错误均有解释。登录、验证、限流或断连时先处理页面或连接，再重新运行。当前商品任务可能留下本轮搜索标签，核对报告后只手动关闭这些任务标签，保留自己的页面。

### 场景 我想每周整理一次已有资料

点击“新建自动化”，标题“每周通勤内容回顾”，提示词：“仅根据当前空间可访问的已有资料，整理本周值得继续核对的三个问题，保留来源与缺口，保存一份回顾草稿。”选择每周、星期和时间；也支持每天、工作日或每小时。保存后检查状态、下次运行和执行摘要，再启用或立即执行。

这类自定义 AI 任务需要对应模型，可能产生费用，也可能进入待确认。点击工作台待处理事项，或“自动化 → 待确认”，审查动作、作用范围和目标，再决定继续或拒绝。批准一项操作不等于以后所有发布都已授权。

任务可暂停、停止当前执行或删除，具体按卡片可用操作处理；停止不能撤回已经发生的外部调用。通知用于发现新结果与异常，执行详情以报告和真实文件为准。

## 17 来源变化后维护已有内容

### 场景 杯子的规格或价格更新 我想找出哪些作品需要检查

**入口：**“研究与选题 → 来源复核”。检查本地入库版本，不补采平台、不调用模型。

1. 先通过明确的采集操作保存新快照，再进入来源复核，选择曾被引用的旧来源版本。
2. 点击“检查当前入库版本”，查看新旧字段与规格差异，以及引用旧版本的证据、机会、直接关联工程和派生工程。
3. 打开原始证据或关联作品，判断变化是否影响该内容。价格须同时检查 SKU、币种与优惠条件；本轮未采到某字段不能直接解释成平台删除了它。
4. 对每项选择“保留历史依据”“计划补充证据”或“计划手动修改”，写理由并勾选确认。
5. 需要修改时，实际打开工程编辑，更新导出，再按原发布流程处理后续版本。回到复核记录查看决定；有新变化时明确重新检查。

**完成标志：**能说明哪件作品因哪个旧引用需要检查，以及已经决定怎样处理。记录“计划修改”并不表示作品已改或平台已更正。旧引用仍保留原版本，系统不会把它自动换成新原文。

扫描只覆盖当前空间登记的工程和关联机会，旧稿件或损坏索引可能不在范围内；出现扫描不完整、排除项或数量限制时，不把结果当成全部作品清单。

## 18 备份 隐私与常见问题

### 场景 我已经完成练习 希望下次能恢复并安全分享

**入口：**“设置 → 通用”“设置 → 隐私与诊断”。

1. 记录工作空间位置。结束任务并退出 GardenFlow 后，备份实际 `gardenflow.db` 和完整 workspace，包括工程与媒体；只有 MP4 或 ZIP 导出并不等于完整应用备份。路径说明与恢复注意事项见[本地部署与备份](./LOCAL_DEPLOYMENT.md)。
2. 梦境项目按分享或完整备份目的分别导出，核对是否包含私密原始记录、历史和参考原图。当前 ZIP 不提供一键恢复。
3. 遇到问题，记录应用版本、系统、空间、停在哪一步、完整错误、期望与实际结果。需要诊断时在“隐私与诊断”导出本地诊断包，必要时打开日志目录；浏览器扩展可单独导出诊断。
4. 分享前检查密钥、身份资料、私密正文与本机路径。报告会脱敏，但仍需自己复核。不要把真实 API Key 放入截图或问题描述。

内容与配置默认保存在本机，没有使用分析或自动诊断上传。使用外部模型时，本轮输入及需要的参考内容会发送给所选供应商；上传平台与导出分享也会让内容离开本机。浏览器采集扩展不申请 Cookie 读取权限，读取内容的时机是手动采集或已启用的自动任务。

### 遇到问题先从哪里查

| 看到的现象 | 建议处理 |
| --- | --- |
| AI 未启用或请求鉴权失败 | 检查该能力路由、自定义供应商、Endpoint、Key、模型与额度，先试纯文本 |
| 文本成功但图片或视频失败 | 单独核对对应能力与模型支持范围，检查视频启用及显式上游类型 |
| 插件已准备但没有连接 | 加载应用导出的正确目录，重载扩展并保持桌面打开；发布另查发布插件 |
| 更新后浏览器仍是旧能力 | 在新桌面版本重新准备插件，再在浏览器重新加载配套扩展 |
| 商品缺参数或评论 | 在原网页展开、等待并重新识别；保存后看缺失提示和来源快照 |
| 资料有视频但没有转写 | 检查转录路由及独立状态，不重复删除已有媒体；百炼原生 ASR 音频编码后上限 10 MB |
| 工程有内容但导出不完整 | 找具体错误页、素材或过期声音，修正后更新导出 |
| AI 修改没有覆盖最新输入 | 检查是否存在新手工编辑或版本冲突，保存后基于最新内容重试 |
| 发布提示已有草稿或错账号 | 去原网页人工核对，再刷新与绑定正确浏览器，重新准备 |
| 发布结果未知或审核中 | 去原账号核实，按原任务流程记录结果，先不要重复提交 |
| 实验显示不足以判断 | 检查两作品的账号、口径、单位、时间窗、观测时间和版本，保留未知限制 |
| 作品或素材突然找不到 | 先核对当前空间、筛选与文件位置，再检查缺失提示和备份 |

### 当前使用边界速查

普通图文卡片需手动上传；商品套图目前支持小红书，编辑上限 20 张、发布上限 18 张。商品视频可为小红书、抖音和 TikTok 分别建版本。梦境故事当前面向 TikTok Studio，完整生成与发布依赖所配服务、账号和页面状态。网页结构、下载权限与平台审核可能影响结果；部分保存和结果未知需要按界面核实。

成组内容和内容实验属于当前开发版能力，模型提出的规划与解释需人工检查；自动风格学习未接入。程序算出的观测差异不证明因果，来源可定位也不保证来源中的主张真实。更多当前限制见[路线图](../ROADMAP.md)。

完成整条路线后，你应能从某一件作品追溯到它的来源、创作依据、可编辑工程、导出文件、发布状态与后续观测；缺少的环节保持明确的待处理状态，再按需要补齐。
