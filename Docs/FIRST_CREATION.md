# 第一次创作：用 GardenFlow 介绍 GardenFlow

[返回首页](../README.md) · [English](./FIRST_CREATION_EN.md) · [演示与验证记录](./DEMO.md)

目标是把一份公开资料变成**可回看来源的介绍稿**。封面是可选的下一步；没有图片服务也可以完成文字稿。本教程不需要浏览器扩展、Embedding 或视频模型。

## 1. 安装并准备模型

从 [Releases](https://github.com/Garden12138/garden-flow/releases/latest) 下载安装包：Apple Silicon Mac 选 arm64 DMG，Intel Mac 选 x64 DMG，Windows 选 x64 exe，Linux x64 选 AppImage 或 deb。当前包未进行 Apple 公证或 Windows 代码签名，系统可能显示安全提示；请确认下载来源并参照[安装与校验说明](./PACKAGING.md)。

GardenFlow 按[非商业 Source-Available 许可证](../LICENSE)提供。应用不提供共享密钥或模型余额；云端模型可能产生供应商费用。本地优先指资料和工作空间默认在本机，使用外部模型时，输入会发送到你选择的供应商。

首次打开后，在“设置 → 通用”确认工作空间目录。接着打开“设置 → AI 供应商”：

1. 点击“添加供应商”，选择与你的服务对应的预设。
2. 填写 Endpoint、API Key 和默认模型。已运行的本地兼容服务可使用本机 Endpoint，Key 可留空。
3. 在“能力路由”将“对话 / 内容创作”设为“自定义”，选择该供应商并填写模型 ID。
4. 点击“保存设置”。先发起一个简单文本请求，确认服务可用；“可用”标识表示配置完整，不保证远端请求成功。

模型需要支持所用功能；需要工具执行的创作任务还要求模型支持工具调用。供应商填写方法和排错见 [AI 供应商配置](./AI_PROVIDERS.md)。

## 2. 添加公开示例资料

打开[示例资料](../examples/first-creation/sources/gardenflow-facts.md)，通过 GitHub 的原始文件下载功能保存为 `gardenflow-facts.md`。也可以下载仓库源码压缩包，只取 `examples/first-creation/`，无需安装 Node.js。

在 GardenFlow 的知识库中点击“添加文件”，选择该 Markdown 文件。检查条目已出现、索引状态可查看，并打开资料确认内容完整。资料包含原始链接、适用版本与能力边界；导入本地文件不会自动变成浏览器采集记录。

未配置 Embedding 时先使用全文检索和明确选择资料，不依赖语义检索。不要把整个私人目录作为这次公开演示的输入。

## 3. 生成并选择一个角度

进入 AI 创作，通过 `#` 或来源选择器加入刚导入的资料；确认输入区确实出现来源，再发送[选题提示词](../examples/first-creation/prompts.md)。

模型会给出三个候选方向。首轮选择“从资料到一篇有来源的介绍稿”，在会话中明确回复自己的选择。这里使用创作会话完成选题，不要求先配置独立的灵感模型。

## 4. 写作、核对与保存

继续发送同文件中的“成稿提示词”。要求引用能回到资料中的公开链接，不编造用户数、Star、速度提升或亲身体验。

人工检查四项：

- 产品能力是否来自资料，实际操作是否真的完成。
- 许可证、模型自配置与外部请求边界是否写清楚。
- 来源链接能否打开，是否支持对应陈述。
- 结果是介绍稿而非自动发布承诺。

让 AI 将核对后的内容保存为稿件；涉及写入确认时审查目标位置。回到稿件页打开结果，确认正文存在、引用保留且可以再次编辑。如果只返回聊天文本而没有实际文件，可复制正文并使用稿件页的新建入口保存，记录这是人工保存。

**完成标准：一份保存后仍能打开、编辑并回看来源的介绍稿。** 不把聊天中出现“已保存”当作文件确实存在的证据。

需要对照时，可查看本仓库[实际运行并人工核对后的介绍稿](../examples/first-creation/output/gardenflow-intro.md)。模型输出不要求逐字相同，事实和来源边界应一致。

## 5. 可选：生成一张封面

在“设置 → AI 供应商”的图片能力路由中，单独选择支持图片生成的供应商和模型并保存。聊天模型可用不代表图片生成已配置。

使用[封面提示词](../examples/first-creation/prompts.md)生成一张封面。生成成功后进入媒体库，预览真实图片、检查文字并定位文件；需要用于稿件时，再绑定或选择该图片。封面上的文字如有错误，修正后再发布。

图片服务未配置或失败时，保留已完成的文字稿，参照[媒体排错](./USER_MANUAL.md#媒体任务没有结果)，无需反复重跑文字任务。

本次案例的[实际 3:4 封面](../examples/first-creation/output/gardenflow-first-creation-cover.png)由应用保存到媒体库后复制到仓库，模型、尺寸和耗时见[验证记录](./DEMO.md)。

## 需要采集网页时再装扩展

1. 在“设置 → 隐私与诊断 → 浏览器插件”点击“准备插件”，再点“打开插件目录”。知识库空状态中的“准备浏览器插件”也可进入准备流程。
2. 在 Chrome、Edge 或 Brave 的扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，加载导出的目录。
3. 保持 GardenFlow 打开，检查知识库插件状态为已连接，然后明确采集一篇允许使用的公开内容。

“插件已准备”只表示导出和 Host 准备完成；浏览器加载并握手后才是“已连接”。平台要求登录或验证时，在原网页完成。安装包用户无需运行 `pnpm build:plugin`。

## 遇到问题

| 现象 | 下一步 |
| --- | --- |
| 未配置 AI，无法生成 | 添加文本供应商，开启“对话 / 内容创作”路由并保存；本地资料仍可管理 |
| 配置完整但请求失败 | 检查实际 Endpoint、模型、协议、供应商额度和网络；先验证简单文本请求 |
| 没有图片服务 | 先完成文字稿，再单独配置图片能力 |
| 插件未连接 | 准备插件、加载导出目录、保持应用打开并检查状态；本地文件教程不依赖插件 |
| 没有生成实际稿件或图片 | 查看任务错误和文件结果；不要仅依据聊天回复判断成功 |

使用问题可到 [Discussions](https://github.com/Garden12138/garden-flow/discussions)；可复现缺陷请提交 [Bug report](https://github.com/Garden12138/garden-flow/issues/new?template=bug_report.yml)。附版本、系统、停在哪一步、期望与实际结果，不要提交密钥或私密资料。
