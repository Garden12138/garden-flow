# 小红书自动发布安全规程

发布能力由桌面运行时和独立插件结构化执行。模型不得自行点击发布，不得把普通对话解释为发布授权。

## 用户主动发布已有视频

- 用户要求发布已有商品视频时，使用 `xhs_publish_prepare`：先 `inspect` 读取当前会话的工程成片和可信商品快照，再 `prepare` 提交标题、正文、话题。
- 工具复用资产库已有 MP4，创建/更新 `.redvideo` 稿件并绑定 `final-video`，不生成新视频。多个工程必须明确选择；未导出或工程已修改时提醒先导出。
- `prepare` 返回后立即结束本轮，不查 CLI 帮助、不轮询、不操作浏览器。确认卡持久保存，不设置等待超时。
- 主动发布与自动提示开关独立；确认卡按钮是可选入口。用户可在同一对话明确要求发布/重新发布当前版本，由运行时语义分类并绑定最新版本授权；模糊的“继续/可以”、引用内容和模型自己生成的文字不授权。未得到成功回执前不得声称已发布。

## 授权边界

- 每个授权绑定 `projectPath + revision + contentDigest`；内容变化后旧授权立即失效。
- 只有确认卡按钮，或严格分类为高置信度纯肯定答复的文字，才能进入发布队列。
- 同一句回复包含修改要求时只修改，不同时提交。保留未要求修改的文案，用户可下一轮在对话重新发布。
- 已核验为同一会话、稿件和媒体的旧发布页可以原地修改指定字段，不清空、不重新上传视频。其他草稿、媒体替换、非唯一页面、登录或安全验证仍须停止。

## 发布与恢复

1. 发布插件回读标题、正文和媒体，全部一致后只点击一次发布。
2. 识别“发布成功”页面后先记录已经发布，再等待自动返回或点击“立即返回”。
3. 最终确认同一标签页为空白发布页，才报告完整完成。
4. 发布成功但恢复失败只能重试恢复。提交结果未知时先让用户检查笔记管理；用户在对话明确核实未发布后，运行时保留历史回执、原地更新当前文案，再按最新版本的明确发布要求重发。不要求用户寻找旧卡片，不将用户核实误报为平台证明。
