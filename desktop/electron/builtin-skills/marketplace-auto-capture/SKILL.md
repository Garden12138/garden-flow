# 淘宝／天猫商品自动采集

任务默认关闭；在「计划 → 自动化」分别配置两个任务的关键词、目标新增商品数、评论标签、每标签条数、节奏和时间，再使用「立即运行」或开启定时任务。桌面端必须运行，已登录浏览器中的采集插件必须连接。任务不调用生成模型。

1. 按天轮换关键词，`research.run` 从指定平台首页的搜索框提交；读取可见真实商品链接，有限等待和滚动。首页推荐不能充当搜索结果。
2. 创建任务自己的商品页，用 `capture.save` 和 `expectedProduct` 校验详情页商品编号，复用侧栏商品与评论提取、图片安全下载及 `assets.ingestProduct`。
3. 评论标签留空默认采当前评价列表 5 条；填写后仅采页面真实标签，每标签 1–50 条，最多滚动 6 次；不根据主题标签推断好中差。
4. 按实际详情页保存 `taobao` 或 `tmall` 来源，不按首页入口推断平台。平台 + 商品编号去重；同平台复采追加快照、保留用户编辑和本地素材，跨平台商品独立保留。关联同款仍由用户确认。
5. 以真实 `productId`、`snapshotId` 为保存成功依据。复采不占新增配额，搜索补读最多 2 次，每轮尝试最多 max(12, 目标数 × 4) 个商品。
6. 保守节奏搜索前等待 5 秒，商品页停留 10–16 秒、商品之间 20–35 秒；连续两个失败停止。登录、安全验证、限流立即停止，不尝试绕过；评论访问受限时已读商品仍入库，报告标记停止原因。
7. 保存结束关闭任务创建的商品页和搜索页；不关闭用户原有标签页。报告按任务和空间写入独立会话，不改变已有创作确认卡。

## 排查

- 关键词未就绪：至少填写一个关键词，可用逗号或换行分隔。
- 插件未连接：打开采集浏览器、启用最新版 GardenFlow 插件，并保持桌面端运行。
- `search_input_unavailable`：搜索框结构未匹配或页面未加载；查看任务报告，在浏览器确认页面状态后再运行。
- `results_not_ready`：有限等待后没有稳定搜索卡片，可能页面结构变化；不能用首页推荐或猜测商品地址继续。
- `login_required` / `security_verification_required` / `rate_limited`：在浏览器由用户完成登录或验证后再运行。
- 商品已保存但评论不完整：查看来源快照及任务报告；已保存的资料和素材继续可用。
